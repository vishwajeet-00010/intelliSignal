**Important note about your own Windows setup.** The simulation was built and executed
in the Linux workspace attached to this session, not in your Windows Python
installation. The project files themselves are on your Windows disk and are ready to
run there, but before the presentation you must confirm that **your Windows machine**
has SUMO and the Python packages installed. Check with:

```
python --version
python -c "import numpy, pandas, matplotlib, yaml; print('python packages OK')"
python -c "import sumolib; print(sumolib.checkBinary('sumo'))"
echo %SUMO_HOME%
```

If the last two fail, install SUMO from <https://sumo.dlr.de/docs/Downloads.php> and set
`SUMO_HOME`, or run `pip install -r requirements.txt` (the `eclipse-sumo` package brings
the SUMO binaries with it).

## 5. How to run the project

```bash
# one scenario, headless, saves CSV
python simulation/run_simulation.py --scenario moderate
python simulation/run_simulation.py --scenario heavy

# live demonstration in the SUMO GUI
python simulation/run_simulation.py --scenario moderate --gui
python simulation/run_simulation.py --scenario heavy --gui

# run a scenario and rebuild the graphs
python simulation/run_simulation.py --scenario moderate --plot

# both scenarios, graphs and a comparison table, in one command
python simulation/run_scenario.py all

# rebuild graphs from existing CSV files
python simulation/plot_results.py

# rebuild the intersection network
python sumo/network/build_network.py

# capture fresh screenshots from a running SUMO
python presentation/capture_screenshots.py

# run the tests
pytest -v tests/
```

## 7. Heavy traffic results

Configuration: `config/heavy.yaml` — 3000 veh/h total. Same network, same signal plan,
same duration and seed as the moderate scenario.

| Metric | Value |
|---|---|
| Vehicles in simulation | 1445 |
| Average waiting time | 51.90 s / vehicle |
| Average queue length | 40.39 vehicles |
| Maximum queue length | 72 vehicles |
| Throughput (completed trips) | 1351 vehicles |
| Still in network at the end | 94 |
| Teleports | 0 |
| Simulation time | 1800 s |

Source: `results/csv/heavy_results.csv`

**Observation, reported as measured.** Demand rises by a factor of about 2.1, average
waiting time by a factor of about 5.2, and average queue length by a factor of about
10.9. Throughput rises in absolute terms (693 → 1351) but no longer absorbs the demand:
94 vehicles are still in the network when the window closes, against 9 in the moderate
case. The teleport count is 0 in both runs, so neither scenario gridlocked artificially.

Both runs use a fixed seed, and re-running the commands reproduces these numbers
exactly — this was confirmed by running each scenario more than once.

## 8. Generated metrics

Collected live through TraCI, per run:

- `vehicles` — vehicles that entered the simulation
- `average_waiting_time` — mean accumulated waiting time per vehicle (s)
- `average_queue_length` — mean halting vehicles on the 8 incoming lanes, averaged over every step
- `throughput` — vehicles that completed their route
- `simulation_time` — simulated seconds executed
- `max_queue_length`, `vehicles_departed`, `vehicles_still_in_network`, `teleports`

Plus a per-second time series: `time`, `running_vehicles`, `queue_length`,
`arrived_cumulative`, `signal_state`, `signal_phase`.

## 13. Current limitations

- Two demand scenarios only.
